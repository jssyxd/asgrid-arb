## 1. 当前真实状态（决策的事实基础）

| 项 | 数值 | 来源 |
|---|---|---|
| 实盘账户 | `accountbot3`，OKX 真实盘 BTC-USDT-SWAP，30 USDT | 【实测】 |
| 单笔最小名义 | 0.01 张 ≈ 8.08 USDT = 总权益 27% | 【实测】 |
| Maker 比例 | 99.5%（旧版 dayuan 为 70.7%） | 【实测】 |
| 手续费 | 10.38 h 累计 0.3269 USDT（旧版 40.96 h 累计 4.92 USDT） | 【实测】 |
| 净捕获率 e | **−0.55 bp/名义** | 【反推】 |
| 逆向选择成本 a | ≈ 3.05 bp/名义（吃掉 67.8% 报价半价差） | 【反推】 |
| 报价半价差 δ | 4.5 bp（总价差 9.0 bp 门槛） | 【实测】代码常量 |
| 价差捕获比例 φ | ≈ 1.0（价差被完整捕获，问题全在逆向选择） | 【反推】 |
| 网络 RTT | 45–75 ms（马来西亚 → OKX 撮合） | 【实测】 |
| 事件循环抖动 | 10–50 ms（1 核 1G 多容器） | 【实测】 |
| OKX 最优价档位生命周期 | 中位 1.73 秒，每 3.8 秒换一次最优价 | 【实测】1 小时 L2 重放 |
| 队列周转 | 买一档平均约 16 秒被清空一次（219 次/小时） | 【实测】 |

**这五个数字锁死了整个方法论的形状**：

1. `e = −0.55 bp` ⇒ 现在的首要任务不是训练模型，是**把 a 从 3.05 压到 2.5 以下**。
2. `a / δ = 0.68` ⇒ 逆向选择吃掉三分之二的毛利。降 a 的手段有三个：更宽的价差、更强的毒性过滤、成交后冷却。**没有一个是「加更多钱」**。
3. `φ ≈ 1.0` ⇒ 队列位置不是当前瓶颈。降 a 之后，队列位置才会成为下一个瓶颈。
4. `RTT 45–75 ms` vs `档位生命周期 1.73 s` ⇒ 延迟不是成交率的杀手（延迟只占档位寿命的 4%），**延迟的真正伤害是「陈旧报价被扫盘」**。迁移东京的收益来自减少穿盘，不是提高成交率。
5. `单笔 = 27% 权益` ⇒ 30U 上不存在「精细做市」，只存在「测量账户」。

## 2. 分层职责与接口契约

### 2.1 层间契约（唯一的真相源）

| 层 | 唯一事实源 | 对下层的输出 | 对上层的输入 |
|---|---|---|---|
| 标的层 | `datapipe/pools/{venue}.json` | 每个标的的 `min_spread_bps` / `max_inventory` / `gamma` / `state` | 无 |
| 数据层 | `silver/events/{dt}/{venue}/{symbol}/{date}/{hh}.parquet` | 统一事件流 | 归档 + 自录双源 |
| 特征层 | **`src/ml/l2_features.py`（离线与实盘共用同一份）** | 特征向量 | 事件流 |
| 标签层 | `src/ml/labels.py` | 标签 + 可观测性断言 | 事件流 |
| 模型层 | `checkpoints/registry/{model_id}/` | `λ̂(δ,side)` / `â(δ,side)` | 特征 + 标签 |
| 决策层 | `src/ml/decision.py` | 目标挂单距离 δ* | 模型输出 + A-S 基线 |
| 约束层 | `live_cluster/as_nautilus_strategy.py` | 最终报价 | 决策层输出 + 账户状态 |
| 回测层 | `src/queue_backtest/` | 收益区间 + CI + OPTIMISM_GAP | 事件流 + 决策层 |
| 监控层 | `live_cluster/ops/` | 告警 | 三层埋点 |

**三条不可违反的契约**：

1. **特征只实现一次**。CI 检查：`grep -rn "def compute_" live_cluster/ src/ | grep -v ml_features` 不得出现第二份实现。
2. **训练与实盘的深度档位必须一致**。实盘用 `books5`（5 档），凡依赖 >5 档的特征必须标记 `F_deep` 并排除出上线模型。
3. **回测与训练必须用同一套队列语义**。否则会出现「训练指标好、回测指标差」的无法解释现象。

### 2.2 打标器的可观测性契约

```python
# 标签定义必须在打标器里显式声明可见性
@dataclass(frozen=True)
class LabelSpec:
    name: str
    horizon_ns: int          # 标签使用未来多少时间的信息
    embargo_ns: int          # 与训练集切分之间的净化期
    observable_at: str       # "decision_time" | "fill_time"
    spec_hash: str           # 参与模型元数据
```

`observable_at != "decision_time"` 的标签，其特征向量必须严格只含 $\le t_0$ 的信息。

## 3. 五个切片的结论摘要与相互依赖

### 3.1 切片 01：标的监控流 + 数据管线

**核心结论**：

- cryptohftdata 已覆盖 14 个交易所（Lighter、Hyperliquid、OKX 全系列），提供小时级 Parquet 归档，含序列号可用于缺口检测。【实测】
- 归档文件路径规范：`{exchange}/{YYYY-MM-DD}/{HH}/{symbol}_{datatype}.parquet`，下载走 302 签名 URL（必须 `curl -L`）。【实测】
- **OKX 上的 RWA/代币化股票点差仅 0.28 bps、24h 成交额仅约 2.78 万 USDT**。【实测】结论：**RWA 在 OKX 上不是价差机会，是 funding carry + 事件驱动机会**，必须走独立漏斗分支。
- HIP-3 符号空间是动态的（`XYZ:` / `CASH:` / `FLX:` 前缀按 dex 生成），符号注册表必须每日重建，禁止硬编码。【实测】
- 单位陷阱是致命的：OKX 永续 `quantity` 单位是「张」，需乘 `ctVal`；Lighter 的 `last_update_id`（offset）不连续不能用于缺口检测；Hyperliquid 的 `tid` 不是序列号。【实测】

**依赖**：切片 01 的数据层产出是切片 02/03 的唯一输入。

### 3.2 切片 02：ML 训练闭环

**核心结论**：

- 模型目标是**每笔净期望（bps）**，不是 AUC、不是胜率。成交概率是计数事件，用 Poisson 强度而非二分类。【建议】
- 标签分五个任务：成交强度、逆向选择成本、有符号成交、不利路径、最优距离残差。【建议】
- **模型只输出两个原语**：`λ̂(δ,side)`（挂多远）与 `â(δ,side)`（要不要挂）。报价由闭式解 `δ* = 1/θ + f_maker + a + c_inv` 反解，不直接回归报价。【建议】
- **推理延迟预算**：特征 <50 μs + GBDT <100 μs + 钳制 <10 μs ⇒ P99 < 200 μs。1 核 1G 可行。Transformer 作主力被排除。【建议】
- **影子成交（paper fill）是最便宜的基础设施**：用真实行情实时产出虚拟成交与 markout，零成本、零手续费，样本量比实盘大两个数量级。**建议第一天就做。**【建议】
- **训练/实盘特征一致性对拍是最高优先级**：同一批原始事件离线重放 vs 实盘在线计算，逐字段 diff ≤ 1e-7。
- 打乱标签检验是防泄漏的照妖镜：成本极低，必须做。

**依赖**：切片 02 的 H4（逆向选择量级）是全局第一号阻塞项。

### 3.3 切片 03：队列感知回测引擎

**核心结论**：

- **自研 Numba 事件引擎为主**。理由：复用现有定价状态机（回测与实盘必须同源）、1 核 1G 可跑（30 天 L2 ≈ 12.8 亿事件，Numba 分钟级，NautilusTrader 小时级）。【建议】
- **不引入 hftbacktest**，但要**照抄它的队列模型公式**（`RiskAverseQueueModel` / `ProbQueueModel`），避免自创语义。NautilusTrader 定位为**语义验收基准**（跑 1 天窗口做逐笔比对）。【建议】
- 三方案并存输出区间：A（保守，下界）/ B（概率，主用）/ C（零排队，上界）。**差值 `C − A` 就是引擎自身的乐观偏差量化。**【建议】
- **双时间轴事件循环**是物理正确性的关键：`exchange_ts` 决定撮合因果，`local_ts` 决定我方何时能看见信息。陈旧报价套利必须能被引擎捕捉。【建议】
- **确定性优先于速度**：`fastmath=False`，随机种子从数据内容派生（splitmix64），禁止 `np.random.seed()`。
- 盈亏平衡延迟 `L*` 用二分法求解。若 `L* < 100 ms`，该参数下策略对延迟零容错，实盘不可行。

**依赖**：切片 03 是切片 02 的评估环境，也是上线许可的来源。

### 3.4 切片 04：实盘 / 资金 / 运维

**核心结论**：

- **关卡制**给出上线许可：影子 → 模拟盘 → 30U 实盘 → 单标的放量 → 多标的 → 资金阶梯。每关有量化准入与退出条件。
- **关卡 2（当前）的正确定位是「测量单位经济学」，不是「赚钱」。** 退出条件是「e 的估计足够可信」，不是「赚到钱」。
- **最小可行资金有公式**：
  ```
  E_min = max( N_min/ρ_grain, N_min·q_floor/λ_max, C_op/(30·k_v·e) )
  λ_max = k_v·e/(SNR_min·σ_1d·ρ_inv)
  ```
  代入当前 `e = −0.55` ⇒ **E_min 无解**。代入 `e = 1 bp, k_v = 30` ⇒ E_min ≈ 1,500 USDT；`e = 2 bp` ⇒ 750 USDT。
- **杠杆不改善期望**，只放大 λ 与破产速度。`λ_max ≤ 1` 的区间内应当拒绝杠杆。
- **多标的不是「分散风险」，是单标的容量天花板的必然结果**（档位数 × 下单速率 × 报价陈旧度三条约束合起来）。
- **监控三层**落在「单个 Python 守护进程 + JSON 状态文件 + Telegram」形态上。**不要**在 1 核机器上引入 Prometheus + Grafana（常驻 700MB–1.2GB，会挤出交易进程）。
- **最重要的一条告警**：`e_rolling_100 ≤ 0` ⇒ 冻结加仓。其余都是辅助。

## 4. 全局第一号阻塞项（按优先级）

| # | 阻塞项 | 为什么排这个位置 | 怎么测 | 若不成立 |
|---|---|---|---|---|
| **B1** | **逆向选择成本 `a` 的真实量级** | 切片 04 反推的 3.05 bp 是从 10.38h 样本反推的，样本极小。若 `a > 2.5 bp`（= δ − 手续费），**任何做市都不可能盈利**，整个方向要重估 | 影子成交 + markout 环形缓冲，实盘 1000 笔 | 方向重估：改做对冲 / 库存即服务 / 换标的 |
| **B2** | **数据湖能否重建订单簿** | 决定 OFI 类逐档特征能否离线重建。若归档是快照而非增量，特征价值腰斩 | 下载 1 小时 orderbook parquet，检查 `prev_final_update_id` 链式连续性与 `quantity==0` 的删除语义 | 退化为快照差分 OFI（近似版） |
| **B3** | **队列前方量分布与真实成交率** | 决定回测方案 B 的参数与实盘成交率上限 | 30 天 L2 回放 + 实盘成交率对账 | 若实测成交率远低于回测，回测全部作废 |
| **B4** | **推理延迟 P99** | 决定 ML 能否上线 | 本机 5000 次推理计时 | > 200 μs ⇒ 走蒸馏路径或放弃 ML |
| **B5** | **RWA/HIP-3 有效撮合时段表** | 决定 RWA 分支能否执行。时段外挂单 = 开市瞬间被扫 | 从 instrument 元数据 + 行情稀疏性反推 + 人工校验 | RWA 分支整体降级为「不交易」 |

**建议执行顺序**：B1 → B2 → B3 → B4 → B5。
B1 只需要一天（影子成交器），且**成本最低、价值最高**。它比训练任何模型都更重要。

## 6. 反幻觉纪律（贯穿所有阶段）

| # | 纪律 | 强制手段 |
|---|---|---|
| 1 | 任何收益数字必须来自真实数据 + 真实撮合 | 回测输出必须附带 `data_manifest.json`（文件 SHA256 + 行数 + 时间范围） |
| 2 | 合成随机数只能用于单元测试，不能用于策略评估 | `src/alpha_gpt_evolution_engine.py` 已整改（真实数据）。CI 检查禁止 `np.random.randn` 出现在评估路径 |
| 3 | 未来函数必须在打标器层被断言 | `labels.py` 的可观测性断言 + 打乱标签检验 |
| 4 | 回测必须出区间不出点估计 | block bootstrap 95% CI + 三方案区间 |
| 5 | 实盘样本只能验证「量级」，不能验证「收益」 | 10.38h 样本禁止用于收益结论（切片 03 §11.2） |
| 6 | 模型部署要求 `dirty=false` | 部署脚本检查 git 状态 |
| 7 | 训练集分布基线必须来自实盘影子，不是回测 | 切片 04 §3.3 明确：`rolling_ofi_60s` 与 `adx14` 在实盘与回测必然不同 |
| 8 | 每次结论必须标注来源 | 【实测】/【推断】/【建议】三选一，无第四种 |
