## 0. 本切片的边界与首要结论

### 0.1 范围

本设计回答五件事：**训练什么**（A）、**用什么特征**（B）、**怎么切分与训练**（C）、**怎么盯漂移与重训**（D）、**怎么把概率变成报价并证明它有用**（E、F）。

不做的事：不设计 L2 撮合回测引擎内部实现（由并行 worker 负责，此处只给接口契约）；不重复 `as_nautilus_strategy.py` 已有的 A-S 定价、ADX、冷却、库存偏置实现；不重新发明 `okx_ws_manager.py` 的 OFI 累积逻辑（此处只做「训练侧要与实盘侧逐位一致」的约束）。

### 0.2 首要结论（决定了后面所有设计）

把共享上下文的实测数字摆在一起：

| 项 | 数值 | 来源 |
|---|---|---|
| 实盘总报价价差下限 | 9.0 bps | 【实测】`run_live.py:157` `min_spread_bps=9.0` |
| Maker 费率 | 0.02% = 2 bps/边 | 【实测】`src/run_2year_asgrid_backtest.py` 手续费设定 |
| 单次成交捕获 | 半价差 4.5 bps | 【实测/推断】4.5 = 9.0/2 |
| 扣手续费后每笔净 | 4.5 − 2 = **2.5 bps** | 【推断】算术 |
| 最小下单单位 | 0.01 张 ≈ 8.08 USDT 名义 = 总资产 27% | 【实测】共享上下文 |
| 单笔毛利绝对值 | 8.08 × 4.5e-4 ≈ **0.0036 USDT** | 【推断】算术 |
| 单笔手续费绝对值 | 8.08 × 2e-4 ≈ **0.0016 USDT** | 【推断】算术 |

**结论 1：在 30 USDT 账户上，做市的第一约束不是"能不能成交"，而是"每笔净期望 > 0"。** 逆向选择成本必须被压到 2.5 bps 以下才有利润。

**结论 2：模型的主战场是"筛掉毒性成交"，不是"提高成交率"。** 任何提高成交率但同步抬高逆向选择的改动，净收益是负的。因此本设计的模型目标函数全部以 **每笔净期望 (bps)** 为核心度量，而不是 AUC、不是胜率、不是成交笔数。

**结论 3：A-S 解析解是基线，ML 只提供两个可解释的原语：**
- `λ`（挂单成交强度的距离衰减率），决定「挂多远」
- `a`（成交后的即时逆向选择溢价），决定「要不要挂」

由这两个原语可以闭式解出最优挂单距离，见 §E。

**结论 4：模型推断必须能在 1 核 1G 上 < 200 μs 完成。** 这直接排除了 Transformer 类方案作为主力（§C.6）。

**结论 5：训练与实盘的特征必须来自同一个模块、同一个深度档位。** 实盘当前用 OKX `books5`（5 档），若离线用全 L2 训练多档形状特征，模型上线即失效且**无法用实盘数据发现**（因为线上根本取不到该特征）。这是本切片最容易被忽略、代价最高的一个坑（§B.7、§F.1）。

## A. 任务定义与标签设计

### A.0 总原则

1. **不做价格方向预测。** 与做市目标无关的方向模型在回测里只贡献噪声。
2. **所有标签必须满足"决策时点可见性"**：在决策时刻 t₀，模型只能使用 ≤ t₀ 的信息。打标允许使用 t₀ 之后的信息（那是标签的定义），但**特征向量绝不能**。
3. **两阶段分解**（全文贯穿）：
   - 阶段 1：`P(成交 | x, δ, side)` —— 会不会被成交
   - 阶段 2：`E[逆向选择 | 已成交, x, side]` —— 成交后会不会被打穿
   - 决策：净期望 = 阶段 1 × (价差捕获 − 手续费 − 阶段 2)
4. **每个标签必须回答**：(a) 标签定义式，(b) 预测时点 vs 打标时点，(c) 是否泄漏，(d) 样本权重，(e) 为什么对做市有用。

### A.1 任务 1：成交概率 / 成交强度模型

#### A.1.1 为什么不是「分类」而是「强度 + 风险集」

挂单成交是**计数事件**，不是二分类。而且「未成交」样本里绝大多数是"根本没人来"（无信息），只有极少数是"来过了但我排在后面"（有信息）。把两者混在一个 0/1 标签里，会让模型退化成「预测有没有人碰我的价」，学不到队列位置的影响。

#### A.1.2 主模型：Poisson 强度模型（带删失）

**标签**：对 (事件时刻 t₀, 挂单价格 P, 侧 side, 窗口 H)，
```
y = Σ_{t ∈ (t₀, t₀+H]}  aggressor_volume_at_or_through(P, side, t)
```
其中对买单（side=bid, P = mid − δ）`aggressor_volume_at_or_through` 是**成交价 ≤ P 的主动卖出量**；卖单对称。

**模型**：
```
log λ(x, δ, side) = g(x) + s(log δ) + side·b(x)
```
- `g(x)`：主模型，共享特征
- `s(·)`：距离项，单调 spline（约束：随 δ 单调不增）
- `side·b(x)`：买/卖不对称（毒性在两侧不同）

**为什么用 Poisson**：
- log-link 天然处理极度不平衡（成交率常在 0.1%~5%），不需要 `scale_pos_weight` 之类的技巧；
- 直接给出"每单位时间的成交次数"，可以自然外推到任意 H：`P(fill ≤ H) = 1 − exp(−λ·H)`；
- 距离项线性进入 log 空间后，**`s` 只有一个全局参数（斜率 θ）**，这对 §E 的闭式解至关重要。

**损失**：Poisson deviance（等价于 `log1p(−exp(−ŷ)) + ŷ − y`，常数省略）。

**替代方案（推荐同时实现，用于交叉验证）**：离散时间风险集模型（discrete-time hazard）。
把窗口切成 1 秒桶，对每个桶 k：
```
h_k(x) = P(在第 k 桶内成交 | 前 k−1 桶未成交)
```
训练时每行是"仍存活"的样本 → 天然处理删失；`P(fill ≤ H) = 1 − Π(1−h_k)`，还能给出**期望成交等待时间**（对库存管理有用：挂多久不成交就撤）。代价是行数 ×H 倍，样本量要求更高。

#### A.1.3 H 的候选值与选型

| H | 用途 | 建议 |
|---|---|---|
| 1 s | 微观扰动尺度，OFI 有效区间 | 【建议】必做，作为微观基线 |
| 5 s | 与 45~75ms RTT + 决策循环同量级 | 【建议】必做，实盘主力对齐尺度 |
| 30 s | 与 1m bar 特征对齐 | 【建议】做，样本效率最好 |
| 300 s | 与 15 秒/60 秒现有特征窗口兼容 | 【建议】做，但只用于库存/撤离决策，不用于报价距离 |

**【建议】** 最终模型用 H=5s 做主输出，H=1s 与 H=30s 作为辅助头/校验（不同 H 的预测应当单调一致：P(fill≤1s) ≤ P(fill≤5s) ≤ P(fill≤30s)，可作一致性单测）。

#### A.1.4 距离网格 δ

**【建议】** δ 以 **mid 的 bps** 为单位（无量纲、与价格水平解耦，便于跨品种迁移）：
```
δ_grid = {0.5, 1, 2, 3, 5, 8, 12, 20, 30} bps
```
在 BTC 价格 ~69,000、tick = 0.1 USDT（0.145 bps）下，0.5 bps ≈ 3.4 tick，30 bps ≈ 207 tick。**【建议】** 网格下界 0.5 bps 是硬约束：小于 3 tick 的挂单在 5 档盘口里与价差无法区分，且极易穿盘变 Taker（共享上下文已实测 Taker 比例曾是灾难：手续费占总亏损 72.6%）。

**【建议】** 训练时**不要为每个 δ 生成独立样本行**（会导致同一时刻的高度相关样本，造成严重乐观偏差）。做法：每行样本包含 (t₀, side)，模型用 `log δ` 作为特征一次性学完整条曲线。样本量因此保持可控。

#### A.1.5 样本不平衡处理

| 手段 | 用法 | 说明 |
|---|---|---|
| Poisson log-link | 主手段 | 平衡问题被 log-link 吸收 |
| 距离特征归一 | `log δ` 减去网格中位数 | 避免数值尺度主导分裂 |
| 时间/深度归一 | 强度除以同期盘口深度 | 让样本跨流动性可比 |
| Winsorize 标签 | 成交量 clip 到 99.5 分位 | 防止单笔巨量把模型拉爆 |
| 类别不平衡技巧 | **不推荐** `scale_pos_weight` | Poisson 下会引入系统性偏置；改用「后验校准」（见下） |

**后验校准（必做）**：Poisson 模型输出的是"平均强度"，实盘需要"概率"。在验证窗上做 **isotonic 校准**（或对低样本段用 Platt），把 `λ̂` 映射到 `P(fill≤H)`。校准曲线（预测 vs 实际）必须随时间滚动监控（§D.3）。

#### A.1.6 样本权重

1. **时间衰减**：`w = 0.5^(age_days / 14)`（半衰期 14 天）——【建议】。加密市场微观结构漂移快，长窗口历史权重大。
2. **成交事件去相关**：同一秒内多次更新同一侧视为一个事件，权重按事件合并（避免高频时段主导）。
3. **无 IPW 需求**（成交模型不需要）：条件是 `P(fill | x)`，不是 `P(事件 | fill)`。

#### A.1.7 标签泄漏检查

- 标签用 t₀ 之后的成交，特征用 ≤ t₀ → **无泄漏**（标准监督学习）。
- **真实风险点在数据拼接**：L2 归档的 book 快照与 trade 流必须**严格按事件时间戳归并**，且同 ts 内 book 与 trade 的相对顺序要靠交易所原始序号（如 OKX 的 `seqId` / `tradeId`）确定。**【建议】** 在 `labels.py` 中加断言：任一 trade 的 ts 不得早于它所作用的 book 快照 ts。
- **【实测警告】** `kaggle_trainer/trainer.py` 曾用 `.bfill()` 引入未来信息（已整改）。本设计的打标器**禁止任何 forward-fill / bfill**，只用 backward-fill 且必须带 `min_periods` 限制。

### A.2 任务 2：逆向选择 / 毒性模型

#### A.2.1 定义

对一次在 t₀ 成交的我们的买单（成交价 P_b，中价 M₀ = mid(t₀)），定义**标记差（markout）**：
```
markout_T = (mid(t₀+T) − M₀) / M₀   （以 bps 表示）
```
- 买单方向：**markout < 0 表示被打穿（毒性）**
- 卖单方向：符号相反

**毒性标签**：
```
y_tox = 1 if markout_T ≤ −X bps  （买单侧；卖单对称）
```
**X 的候选**：2 / 4 / 8 bps。**【建议】** X=4 bps 为主（接近半个半价差 4.5 bps，超过即意味着"这一笔白干甚至倒亏"），X=2 bps 作敏感度，X=8 bps 作尾部风险监控。
**T 的候选**：1s / 5s / 30s。**【建议】** T=5s 为主标签（与决策尺度对齐），T=30s 用于库存回吐判断。

#### A.2.2 标签构造与"中间价"的定义

**关键细节**：mid 应该是**成交时刻**的 mid，且必须用**全档或至少 5 档 BBO** 的中价，不用成交价。用 K 线 close 近似会引入对齐误差（现有 trainer 用 1m bar 的 low/high，粒度太粗，不适合做 markout）。**【建议】** 用事件流重建 mid：`mid(t) = (best_bid + best_ask)/2`，或 `microprice` 的低阶版本。

#### A.2.3 训练样本与选择偏差（本任务最容易做错的地方）

模型要回答的是：**在决策时刻 t₀ 看到 x 的情况下，挂单成交之后的 markout 期望是多少**。即 `E[markout_T | filled, x_{t₀}]`。

但训练样本只有"已成交"的记录，而成交是**被 x 相关的选择事件**（信息型订单更愿意吃掉你的单）。直接拟合 `E[markout | filled]` 然后在决策时使用，会产生**选择性偏差**：模型高估在 x 下的成交质量。

**【建议】** 用两阶段 IPW 修正：
1. 用 OOF（out-of-fold）交叉预测的成交概率 `p̂_fill(x_{t₀})` 作为权重：
   ```
   w_i = 1 / max(p̂_fill_i, ε)   （ε = 0.02 截断）
   ```
   OOF 概率必须来自**同一 walk-forward 折内**的预测（否则 IPW 权重本身含未来信息 → 二次泄漏）。
2. 归一化：`w_i ← w_i · (Σw / Σw_raw)`，并对权重做 winsorize（99 分位），防止少数极端权重主导。

**【建议】** 权重方差诊断：计算有效样本量 `ESS = (Σw)² / Σw²`。若 `ESS / N < 0.3`，说明样本选择性太强，**不要训练该模型**，退回到"按 fill 事件类型分层"的做法（§A.3）。

#### A.2.4 目标形式

**不要只训分类。** 分类概率进入不了"净期望 bps"的目标函数（它是阈值化的，丢失幅度信息）。
**【建议】** 主模型是**回归**：
```
markout_reg = clip(markout_T, −30, +30) bps，Huber 损失 (δ=3)
```
同时训一个**尾部分类器** `P(markout ≤ −4 bps)`，用于硬性断路（例如 > 0.6 时该侧禁止挂单，对齐现有 `p_tox >= 0.65` 的语义）。

**回归 + 分类双头**：回归给期望值（进入目标函数），分类给尾部概率（进入风控层）。

#### A.2.5 样本权重汇总

```
w_i = 0.5^(age_days/14)        # 时间衰减
    × (1 / max(p̂_fill_i, 0.02)) # IPW 修正选择偏差
    × clip(winsorize)          # 截断
```
并按 `side` 分开归一（买/卖两侧的 markout 分布不对称，混在一起会让回归项相互抵消）。

### A.3 任务 3：有符号成交模型（方向分解）

#### A.3.1 一个必须先纠正的直觉

朴素想法："把成交概率拆成被主动买单吃掉 / 被主动卖单吃掉"。**对被动挂单而言这是退化的**：被动买单只可能被主动卖单打，卖单只可能被主动买单打。也就是说，"方向"完全由自己挂在哪一侧决定，不含额外信息。

**真正的信息在"成交后价格往哪走"，而不是"对手是买方还是卖方"。** 因此本任务重新定义为三个有决策含义的子目标：

#### A.3.2 子目标 3a：成交后 markout 符号模型（有符号）

```
y_sign = 1 if markout_T > 0 else 0     （对买单；卖单对称）
```
**模型输出**：`p_win = P(markout_T > 0 | filled, x)`。

**决策用途**：净期望的逆向选择项可以写成
```
E[markout | filled] = E[markout | markout>0]·p_win + E[markout | markout≤0]·(1−p_win)
```
分类概率本身不可用，但它是**分位数回归的中间量**，让模型学会"成交后价格更可能往上还是往下"，这个不对称性直接影响买/卖两侧的距离分配。**【建议】** 与 §A.2.4 的回归头共享特征，作为**辅助头**训练（多任务），不单独上线。

#### A.3.3 子目标 3b：成交方式（扫盘 vs 单笔）

对每次成交打标：
```
y_sweep = 1 if 该次成交的主动方在成交瞬间跨了 ≥ 2 个价位（或成交量 > 同期 60 秒成交量的 90 分位）else 0
```
**决策用途**：扫盘成交是信息型（毒性高），单笔小单成交是流动性提供型（毒性低）。
**【建议】** 把 `y_sweep` 作为特征（成交时才知道，所以只能用于**成交后的库存决策**，例如扫盘后立即加宽/暂停），**不能**用于决策时刻的报价距离。但它对**库存回吐时机**（任务 4）非常有用。

#### A.3.4 子目标 3c：主动流方向持续性（成交前的可用信号）

```
run_len = 连续同向主动成交的笔数（在最近 100 笔内）
```
这是**决策时刻可用**的特征，不是标签。它同时是 §A.3.2 标签的**辅助监督信号**：**【建议】** 用 `run_len` 的符号作为弱标签预训练一个"下一笔主动成交方向"模型（自监督预训练），再微调到成交相关任务——这是在 1 核 1G 上比 Transformer 预训练现实得多的路子。

#### A.3.5 有符号模型的样本权重

与 §A.2.5 相同（IPW + 时间衰减），但**按 side 分开训两个模型**（买侧、卖侧各一套参数），避免符号抵消。**【建议】** 两侧样本量差异大时，样本少的侧加 `sample_weight` 平衡，或先训"共享主干 + 侧别 embedding"的结构。

### A.4 任务 4：最短盈利路径 / 深度估计模型

这一组服务**库存回吐时机**与**结构性风险**（什么时候该主动平仓而不是等被动成交）。

#### A.4.1 不利路径模型（MAE）

```
MAE_h = max_{t ∈ (t₀, t₀+h]} max(0, −(mid(t) − mid(t₀)))   （买单侧，bps）
```
标签：`y_mae = MAE_h / 1 bps`（回归），h ∈ {1s, 5s, 30s}。

**决策用途**：如果成交后的 30 秒内价格平均还会继续不利移动 3 bps，那么这一笔的实际净收益远低于 4.5 bps 的表面捕获，应当**在成交后主动平掉**（付 5 bps taker 费换确定性）而不是继续被动挂着等回吐。

**这是本设计里第二个高价值模型**，因为它直接对应"付 taker 费平仓 vs 继续承担风险"的决策，费用是明码的（5 bps），比距离优化更可控。

#### A.4.2 盘口补单/消耗模型（队列反馈）

我们的挂单在队列中的位置会随盘口补单变化：
```
refill hazard: P(某档位在被消耗后 R 秒内被补回 | 特征)
depletion hazard: P(最优档在 Δ 秒内消失 | 特征)   ← 结构性断点（撤单潮/插单）
```
**决策用途**：
- 补单速度 → 我们的队列前移 → 成交概率上修（**这是 Poisson 静态模型缺失的关键反馈**，必须建模，否则在高换手时段系统性低估成交率）
- 档位消失 → 我们的挂单变成"跨档"单（脱离原队列），成交后逆向选择显著变差 → 触发**报价重建**（撤单重挂）

**【建议】** 这两个 hazard 是**规则化**的（用指数平滑估计半衰期），先用规则实现（参数化简单、延迟低），只有当残差检验显示明显预测力时才上 ML。

#### A.4.3 深度估计的"可用深度"

```
adv_depth(δ) = Σ_{levels with |p − mid| ≤ δ} size
```
用途：估计我们的挂单"厚"到什么程度时会被整层吃掉（从而变成 Taker 风险）——虽然有 Post-Only 保护，但厚单在快速行情中仍可能被扫。**【建议】** 作为硬约束层的输入（§E.4）。

### A.5 任务 5（可选）：最优挂单距离的残差学习

**【建议】** 保留但排在最后。因为它的标签最贵（需要反事实回测），而且如果任务 1/2 做好了，闭式解已经覆盖了大部分收益。

#### A.5.1 残差目标的定义

不直接回归 `δ*`，而是回归**两个原语的残差**：
```
residual_λ = g_true(x) − g_base(x)
residual_a = a_true(x) − a_base(x)
```
其中基线 `g_base` / `a_base` 是「只用 A-S + 盘口静态量（spread、深度）」就能算出的部分。模型输出残差，最终原语为 `λ̂ = λ_base·exp(r̂_λ)`、`â = a_base + r̂_a`。

**残差化的收益**：目标方差大幅下降（静态量解释了大半），模型只需学"ML 增量"，对样本量和稳定性要求都降低；同时基线可退化为纯 A-S（§E.5 降级路径）。

#### A.5.2 `δ*_empirical` 的构造（标签）

**【建议】** 以 1 小时为窗口，在窗口内对每个候选 δ 计算反事实净收益：
```
Π(δ) = Σ_{fills simulated at δ} (δ − fee − markout_actual)
```
并取 `argmax_δ Π(δ)` 作为该窗口的 oracle 距离。**注意**：这个反事实必须由**队列感知回测**给出（§F.2），不能用"碰到即成交"的近似，否则学到的距离会系统性偏近（因为乐观地认为远处也能成交）。

**【建议】** 标签噪声大、窗口多 → 只训"小时级粗粒度"的残差，用它做**全天距离档位**的微调（例如"今天整体距离应当比 A-S 基线宽 15%"），而不是逐事件距离。

| 任务 | 打标是否需要未来信息 | 决策时刻可用性 | 泄漏风险点 | 建议优先级 |
|---|---|---|---|---|

## B. 特征体系

### B.0 通用约定

- 所有特征**以 mid 的 bps 为单位**或**无量纲化**（除价格本身），保证跨品种/跨价位可迁移。
- 全部**严格因果**：滚动窗口只含历史；禁止 `bfill`；禁止用当前 bar 的 close 派生需要 bar 结束才知的信息（除非该特征只在 bar 结束后才用于决策，这一点必须逐特征标注）。
- 事件时间统一为 `ts_ns`（交易所时间戳 + 本地接收时间双存）。**【建议】** 特征同时记录 `event_lag_ms`（交易所 ts 到本地接收的延迟）作为质量标记；延迟异常的数据在打标时剔除。

### B.1 微观价格与点差层

| 字段 | 公式 | 说明 |
|---|---|---|
| `mid` | `(P_b1 + P_a1)/2` | 基础 |
| `spread_bps` | `(P_a1 − P_b1)/mid × 1e4` | 报价质量 |
| `imb_q1` | `(Q_b1 − Q_a1)/(Q_b1 + Q_a1)` | 顶档不平衡 |
| `microprice_q1` | `(P_b1·Q_a1 + P_a1·Q_b1)/(Q_b1 + Q_a1)` | 一档加权微观价 |
| `microprice_k` | 见下 | k 档加权（k=3 或 5） |
| `micro_dev_bps` | `(microprice_k − mid)/mid × 1e4` | 微观价偏离中价（**最有用的单值**） |
| `tick_ratio` | `spread_bps / (tick_size/mid×1e4)` | 价差含几个 tick |
| `mid_ret_1s` | `log(mid_t / mid_{t−1s}) × 1e4` | 中价变化率 |
| `mid_ret_1m` | 同上 1 分钟 | |
| `quote_age_ms` | 本地 now − 最近一次 book ts | 陈旧度 |

**k 档加权微观价定义**（标准做法）：
```
M_k = ( Σ_{i=1..k} P_bi·Q_ai + P_a1·Σ_{i=1..k} Q_bi ) / ( Σ_{i=1..k} Q_bi + Σ_{i=1..k} Q_ai )
```
含义：把"顶档空方量"当作买方的成交意愿，把"顶档买方量"当作卖方的成交意愿，权重展开到各档价格。

**多个权重形式**（全部保留，让模型自己选，但**必须注明哪个是线上主用**）：
1. `M_q1`：仅顶档（最常用）
2. `M_k`：k 档展开（k=3/5）
3. `M_exp`：按距离指数衰减权重 `w_i ∝ e^{−λ·d_i}`
4. `M_imb`：仅不平衡比例版本 `P_b1 + (P_a1 − P_b1)·Q_b1/(Q_b1+Q_a1)`

**【推断】** 微观价对**短期（秒级）**mid 移动有预测力（Stoikov 2018），但在 5 秒以上尺度通常被 OFI 包含。**【建议】** `micro_dev_bps` 必须保留，它是最便宜的信号。

### B.2 Cont-Kukanov-Stoikov OFI 层

**逐档 OFI 定义**（严格按原论文）：
```
e_n = 𝟙(P_b,n ≥ P_b,n−1)·Q_b,n − 𝟙(P_b,n ≤ P_b,n−1)·Q_b,n−1
    − 𝟙(P_a,n ≤ P_a,n−1)·Q_a,n + 𝟙(P_a,n ≥ P_a,n−1)·Q_a,n−1
```
（bid 上涨或加量 → 正；ask 下跌或减量 → 正）

| 字段 | 公式 |
|---|---|
| `ofi_l1` | `e_1` |
| `ofi_cum_k` | `Σ_{n=1..k} e_n`（累积 OFI） |
| `ofi_w` | `Σ_n w_n e_n`，`w_n = 1/n`（多档加权） |
| `ofi_slope` | 对 `(n, e_n)` 做最小二乘拟合的斜率（**OFI 斜率**：正斜率表示深处档位也在被主动吃掉，冲击更持久） |
| `ofi_z` | `ofi_cum_k` 除以过去 60 秒同量滚动标准差（**必须做归一**，见 §B.7） |
| `ofi_flow_ratio` | `ofi_cum_k / (Σ Q_b1..k + Σ Q_a1..k)`，即"净挂单压力相对盘口厚度" |
| `ofi_accel` | `ofi_z` 的一阶差分 |

**窗口化**：OFI 应同时保留**事件级（每条 book 更新）**和**滚动聚合（1s / 5s / 60s）**两个层次。现有 `okx_ws_manager.get_rolling_ofi()` 已实现 60 秒窗口，**【建议】** 训练侧必须与之逐位一致（§F.1）。

**【推断】** CKS 论文在标普 500 成分股上给出的 OFI→价格冲击关系，在加密永续上量级不同（tick 更小、杠杆更高、更新更快），**必须本地重估**（§9）。

### B.3 盘口形状层

| 字段 | 公式 |
|---|---|
| `depth_slope_bid` | 对 `(dist_i, Q_bi)`（i=1..k）做 `log Q = a + b·dist` 的最小二乘斜率 b（b<0 表示深度随距离衰减） |
| `depth_slope_ask` | 同上 |
| `depth_curv` | `log Q` 拟合的二次项系数（凸性） |
| `convexity_val` | 订单簿"价值函数"的凸性：`V(q) = Σ_i p_i·min(size_i, q)`，计算 `V''` 的离散近似 |
| `conc_top1_top10` | `Σ top1 档量 / Σ top10 档量`（集中度） |
| `depth_asym` | `(ΣQ_b − ΣQ_a)/(ΣQ_b + ΣQ_a)` |
| `book_gap_flag` | 相邻档位价格是否不连续（有 gap） |
| `liquidity_depth_bps` | 归一化深度：`Σ Q (≤ δ 档) / Σ Q (全部档)` |

**凸性的经济学含义**：`V''(q)` 衡量"我吃掉盘口的价格冲击"。凸性高 → 大额挂单会被吃得很痛 → **大额成交的逆向选择成本更高** → 厚单应该主动减量。这是 A.4.1 MAE 模型的重要特征。

**注意**：offline 若用 10/20 档而 live 只有 5 档，`conc_top1_top10`、`convexity` 等**无法复现**。**【建议】** 分两套特征集：
- `F_common`：只用 5 档（books5 实时可得），**主力模型只用这一套**
- `F_deep`：10/20 档（仅离线有），**仅用于离线探索与未来 live 升级到 books50 后的迁移预训练**

绝不能让上线模型的特征依赖 `F_deep`。

### B.4 毒性 / 主动流层

| 字段 | 公式 |
|---|---|
| `act_buy_vol_5s` | 主动买入量（成交价等于 ask 的部分）5 秒滚动和 |
| `act_sell_vol_5s` | 主动卖出量 |
| `act_imbalance_5s` | `(V_buy − V_sell)/(V_buy + V_sell)` |
| `large_trade_ratio_1m` | `Σ(size > p95(size, 1m)) / Σ size` |
| `large_trade_z` | `(当前主动量 − μ_60s)/σ_60s` |
| `trade_sign_autocorr_100` | 最近 100 笔成交方向序列的一阶自相关 |
| `trade_run_len` | 当前同向连续笔数（对称，sign 取方向） |
| `vpin_bucket` | VPIN 变体，见下 |
| `sweep_intensity` | 单位时间内跨档扫单的次数 |

**VPIN 变体**：经典 VPIN = `Σ|V_buy − V_sell| / (n·V_bucket)`，按成交量桶（每桶 = 平均成交量的 k 倍）计算。加密市场对 VPIN 争议较大（流动性提供者的逆向选择具有反身性）。**【建议】** 用**短窗口**（最近 20 桶）与**中等窗口**（100 桶）两个版本，桶大小取 `2× 平均笔成交量`，并且**必须做自相关归一**——原始 VPIN 在高强度期天然升高，容易变成"波动率代理"。

**【建议】** 毒性层特征一律做 **60 秒滚动 z-score 归一**，否则跨时段不可比。

### B.5 统计 / 微观结构因子层

| 字段 | 公式 | 窗口 |
|---|---|---|
| `roll_cov` | `Cov(Δp_t, Δp_{t−1})` 的滚动估计 → Roll 有效价差 `2√(−Cov)` | 30s / 300s |
| `amihud_illiq` | `mean(|r|) / mean(volume)`（bps per 单位成交量） | 60s |
| `hasbrouck_impact` | 成交量对价格变化的回归斜率（price impact per volume） | 300s |
| `rv_5s / rv_1m / rv_5m` | `√(Σ r²)` 的年化/缩放实现差 | 多窗口 |
| `rv_ratio` | `rv_5s / rv_1m`（**短期波动爆发比**） |
| `jump_flag` | 双变差 BV 与 RV 的比值 `BV/RV < 0.5` → 跳跃 | 1m |
| `vol_imbalance` | `(V_buy − V_sell)/(V_buy + V_sell)` 的成交量版本（与 `act_imbalance` 区别在于按 bar 汇总） | bar |
| `spread_z` | 当前 spread 相对过去 5 分钟中位数的 z-score | 300s |
| `depth_z` | 同上，盘口深度 | 300s |

**Hasbrouck 的重要限制**：它需要**成交序列**且对窗口选择敏感。在 tick 级可以直接做（用 trade 级 Δp 与成交量），但若用 1m bar 聚合就退化。建议 **【建议】** 用 5s 滚动窗口的 trade 级实现。

**Amihud 的重要限制**：单位成交量成交额随价格水平与合约规格变化，**不可跨品种直接比较**，必须除以当日成交额中位数做归一。

### B.6 跨交易所层（多交易所做市）

| 字段 | 公式 | 备注 |
|---|---|---|
| `xd_mid_diff_bps` | `(mid_okx − mid_bench)/mid_bench × 1e4`，bench = binance_futures | 直觉：基准所领先还是落后 |
| `xd_lead_lag_corr` | `corr(ofi_bench(t−τ), ofi_okx(t))`，τ ∈ {0, 50ms, 100ms, 200ms} | **领先关系随时间变**，用滑动窗口 corr |
| `xd_ofi_diff` | 两所 OFI 归一后的差 |
| `funding_rate` | 永续资金费率（年化） | 慢变量，作为 regime 特征 |
| `basis_bps` | `(perp − spot)/spot × 1e4` | 现货-永续基差 |
| `cross_venue_depth_asym` | 两所顶档深度不对称之差 | 跨所流动性泄漏 |

**【建议】** 跨所特征全部标 `slow`，因为它们的信号强度通常在秒级以下，且**依赖第二路行情的采集延迟**——VPS 只有 1 核，第二路 WS 采集 + 解析会挤占主行情的 CPU 与延迟预算。

**【实测/约束】** 1 核 1G 多容器共享 CPU，事件循环抖动 10~50ms。**结论：跨交易所层在当前 VPS 上不推荐上线**，除非把第二路行情做成"低频（1s）快照"而非全量事件流。**【建议】** 第一版模型只用 `F_common`（单交易所 5 档）。

### B.7 「看起来有用但实盘会失效」的特征及失效机理

| 特征 | 失效机理 | 缓解 |
|---|---|---|
| 未归一的 OFI | **低流动性标的上被单笔大单污染**：一次 500 BTC 的撤单使 `e_n` 跳几个数量级，模型学到"撤单 = 要涨"这种伪规律 | 强制 60 秒 z-score 归一 + winsorize；加入深度归一 `ofi_flow_ratio` |
| 深度斜率/曲率（用全档算） | 实盘只有 5 档，`depth_slope` 离线是 20 档回归，线上无法复现 → 线上取到的值分布完全不同 | 拆 `F_common`/`F_deep`，主力只用 common |
| `conc_top1_top10` | 同上，且 top10 在 5 档书里恒等于 top5 | 改名为 `conc_top1_top5` 用于 common 集 |
| Amihud | 单位成交量成交额随价格/合约规格变化，跨时段不可比 | 除以当日成交额中位数 |
| VPIN 原始值 | 高强度期天然升高 → 变成波动率代理，与 `rv_5s` 共线，模型把两者当同一件事 | 自相关归一 + 与 `rv` 做正交化（对 `rv_5s` 残差化） |
| Hasbrouck | 窗口敏感；用 bar 聚合时完全退化 | 固定 5s trade 级窗口，做窗口敏感性检验 |
| `spread_bps` | tick 粒度导致在小价差时段量化跳变；低位价标的 tick 占比大 | 加 `tick_ratio` 作为补充，用 `spread_bps` 的 tick 数做主变量 |
| 深度绝对值 | 跨品种不可比，且受合约规格影响 | 一律除以 `adv_depth` 或使用无量纲比值 |
| 跨所 lead-lag | 采集延迟差导致虚假领先；本 VPS 抖动 10~50ms 直接淹没 50ms 级领先 | 结论：当前不上线 |
| 任何用 `close`/`low`/`high` 派生并同 bar 使用的 1m 特征 | **bar 内 lookahead**：收盘才知道的极值被用来预测同一 bar 的成交 | 一律用事件流重建；bar 级特征只允许用**上一根完整 bar** |

### B.8 特征延迟预算（1 核 1G，单线程，NumPy 标量循环实现）

**【建议】** 增量式实现：每个事件只更新受影响的量，不重算全量。

| 环节 | 每次事件耗时（μs，推断，需本机实测校准） | 备注 |
|---|---|---|
| 盘口状态更新（5 档数组 + 上一快照） | 5 ~ 15 | NumPy 小数组，避免对象开销 |
| 逐档 OFI（5 档） | 10 ~ 25 | CKS 公式逐档 |
| 微观价 / 形状特征（≈ 25 个标量） | 8 ~ 20 | |
| 主动流 / 毒性增量（成交） | 3 ~ 8 | deque + running sum |
| 滚动窗口统计（60s/300s） | 2 ~ 6 | O(1) 更新 |
| LightGBM 推理（≤ 200 树、≤ 31 叶、1 线程、24 特征） | **30 ~ 80** | 需本机实测（§C.6） |
| 硬约束钳制 | 3 ~ 8 | |
| **单次决策合计** | **60 ~ 165** | **满足 < 200 μs 目标** |

**吞吐**：books5 推送 + 成交，事件率约 10~40 次/秒 → 单决策 165 μs ⇒ CPU 占用 < 0.7%，**不构成瓶颈**。瓶颈是网络 RTT（45~75ms，实测）与事件循环抖动（10~50ms，实测）。

**【建议】** 延迟预算的分配原则：**特征更新 < 50 μs，模型 < 100 μs**。若某特征让特征更新超过 50 μs，砍掉它或降级到 1 秒聚合。

### B.9 特征有效性监控（线上）

**【建议】** 每个特征的"预测力"用**滚动 IC** 衡量，每 1 小时更新一次：

```
IC(f, label) = Spearman corr( f_{t}, y_{t+H} )   （窗口 6h / 24h / 7d）
```
- 记录每个特征对**每个标签**（fill / tox / mae）的 IC 时间序列，落盘。
- **告警条件**：
  - `|IC_24h| < 0.01` 且 `|IC_7d| < 0.02` → 该特征对当前标签已无区分度
  - `|IC_24h| < 0.5 × |IC_30d|` → **IC 衰减过半**，特征边际价值下降
- **动作分级**：
  1. 黄：IC 衰减 → 降低该特征在训练中的权重 / 提高时间衰减半衰期敏感性
  2. 橙：连续 3 个窗口 IC ≈ 0 → 从下一次重训的候选集中移除（进入 `feature_retired` 列表）
  3. 红：模型线上收益转负且与某特征强相关 → 立即回滚（§D.5）

**【建议】** 同时监控**分布漂移**（PSI/KS，§D.3）与**IC 衰减**。两者必须分开看：
- 分布漂移但 IC 不变 → 特征值域变了（可能无害，如价格水平变化）
- IC 下降但分布不变 → **关系本身失效**（真漂移），这是更危险的信号

## C. 训练与验证协议

### C.1 数据集定义

**【建议】** 样本粒度：**决策时刻 t₀**（不是固定时间栅格）。
- t₀ 取集合：每条 book 更新（去抖后 ≥ 20ms）或固定 100ms 栅格（**【建议】** 先用固定 100ms 栅格，样本规整、实现简单；后续再上事件驱动）。
- 每行样本：`(t₀, side, features(x_{t₀}), δ 网格标签集合)`。
- **标签集**：fill（强度/计数）、tox（markout 回归 + 分类）、mae。**【建议】** 一次打标、多个任务共享，避免重复解析事件日志。

**特征矩阵的"同刻多行"问题**：同一个 t₀ 会有买侧/卖侧、多个 δ。**【建议】** 不展开成多行（否则同一时刻样本高度相关，交叉验证会高估），而是把 side 与 log δ 作为**特征**，让模型一次学出整条曲线。

**样本量估算**：
- 100ms 栅格 → 86400 行/天；30 天 = 260 万行。
- 24 个 float32 特征 → 260万 × 24 × 4B = **250 MB**。**【推断】** 在 1G 内存的 VPS 上训练 LightGBM 需要约 2~3 倍内存（建直方图），**超预算**。
- **【建议】** 训练不在 VPS 上跑（§8）；VPS 只做推理与监控。

### C.2 时间序列切分：Walk-forward + Purge + Embargo

**禁止随机切分。** 金融时序相邻样本强相关，随机切分等价于让模型在训练集里见过测试期的市场状态。

#### C.2.1 方案参数

**【建议】** 默认配置：

| 参数 | 取值 | 理由 |
|---|---|---|
| 训练窗 | 30 天 | 覆盖足够多的流动性状态 |
| 验证窗 | 3 天 | 早停与超参选择 |
| 测试窗 | 1 天 | 与每日重训节奏一致 |
| 步长 | 1 天 | 每天一个折 |
| 折数 | 覆盖 90 天 → 60 折 | |
| **embargo（净化期）** | **= H_max + T_max + 标记平滑窗** | 见下 |

**embargo 长度计算**：
```
embargo = max(H_fill, H_tox, H_mae) + max(T_markout, T_mae) + bar_smoothing
        = 300 s (H=300s 头) + 60 s (T=60s 标记) + 60 s (1m bar 特征平滑)
        ≈ 420 s ≈ 7 分钟
```
**为什么需要 embargo**：测试窗起点 t 的样本，其标签窗口覆盖到 t + H。若训练集包含 t 附近（训练窗末尾）的样本，**这些样本的标签使用了测试窗内的市场状态**。这不是普通的信息泄漏，而是**标签重叠泄漏**（López de Prado 2018）。它比普通 CV 泄漏更隐蔽：即使训练/测试在时间上不重叠，"训练样本的标签答案"本身包含了测试期的价格。

**【建议】** 实施细节：
- 训练窗末端向前砍 `embargo` 长度（purge：删除与测试窗标签窗口重叠的训练样本）。
- 测试窗之后也留 `embargo` 长度不训练（防止串行相关）。
- 代码里**必须**有一个显式的 `assert_no_overlap(train_idx, test_idx, label_horizon)`，并写进单测（§F.4）。

#### C.2.2 Purged K-Fold（用于超参搜索与样本量充足时）

标准实现（López de Prado）：
```
对每一折 k（测试集 = 连续段 I_k）：
  1. purge:   从训练集移除与 [t_start(I_k), t_end(I_k) + H_label) 有重叠的样本
  2. embargo: 移除测试集之后 embargo 长度内的样本
  3. 用剩余样本训练
```
**【建议】** 我们的场景**以 walk-forward 为主**（因为实盘部署是时间向前的），Purged K-Fold 只用于**训练集内部的超参选择**（避免用最终测试窗调参）。二者不混用。

#### C.2.3 标签重叠的具体实现

事件日志中每个样本 t 的标签是"未来窗口内的统计量"。要判断两个样本是否重叠，需要知道每个样本的**实际标签区间** `[t, t + W_t]`，其中 `W_t` 是该样本的标签依赖长度（不是标称 H，而是**实际用到的事件范围**）。

**【建议】** 实现：
```python
def label_intervals(events, samples, max_horizon):
    # 对每个样本返回 [t_start, t_end]，其中 t_end = 最后一个被标签使用的事件时间戳
    # 通过反向扫描累积"未来被引用的事件"来精确计算，避免用保守的常数 H
```
**精确区间 vs 保守常数**：常数 H 简单但过度 purge（丢掉大量样本）；精确区间能保留更多样本且不泄漏。**【建议】** 先用保守常数（简单、正确），样本量足够后再上精确区间。

### C.3 训练目标函数

**【建议】** 三层目标，从松到紧：

**第 1 层（模型层）**：
- fill 模型：Poisson deviance（或 hazard 的 logloss）
- tox 模型：Huber 回归（clip 到 ±30 bps）+ BCE 分类头
- mae 模型：Huber 回归

**第 2 层（决策层，闭式）**：见 §E。

**第 3 层（端到端可微做市效用）**：题目要求的自定义目标，形式为
```
L(θ) = E[ 1{filled} · ( capture(δ) − fee − AS(δ) ) ]  −  λ_inv · E[ q_t · (mid_t − mid_0) ]
```
其中 `δ = δ_θ(x)` 由模型输出参数化（如 `δ = softplus(w·x)`，`w` 是 θ）。
- **【推断】** 这个目标可以写，但**不建议作为第一版的主训练目标**，原因：
  1. 梯度要穿过"是否成交"的离散事件 → 估计方差极大；
  2. 样本复杂度高（需要策略交互数据），1 核 1G / 30 天数据不现实；
  3. 结果不可解释、不可增量更新（换一批数据要重训策略而非重标模型）。
- **【建议】** 把它作为**离线研究项**：在 Kaggle 上用队列感知回测生成策略级样本，训练一个 end-to-end 策略，与"两阶段 + 闭式"方案做对照，量化两阶段方案损失了多少。

**【建议】** 模型层与决策层之间的"桥梁"必须是**可校准的**：Poisson 强度 → `P(fill≤H)` 的校准要在**验证窗**上做，且校准器随模型版本一起版本化（§D.6）。

### C.4 模型选择度量（比 AUC 重要得多）

**【建议】** 模型排序的主度量（按优先级）：

1. **每笔净期望 (bps)** = 捕获 − 手续费 − 逆向选择，**在队列感知回测上**测得。
2. **净期望的稳定性**：逐日净期望为正的占比（≥ 70% 才可上线）。
3. **决策阈值一致性**：真实 P(fill≤H) 与预测值的 Brier 分数 + 校准曲线斜率。
4. **相对基线的增量**：相对"A-S 解析解 + 现有硬约束"的净期望增量（bps/笔）。**上线门槛建议 ≥ 0.5 bps/笔**（【建议】，需根据实测方差校准）。
5. AUC / logloss（辅助，不作为决策依据）。

**【建议】** 关键：**AUC 提升 1% 可能对应净期望 −0.3 bps**。因为做市的收益是"薄利 × 高频"，AUC 的提升若来自更激进的成交预测，往往伴随逆向选择上升。

### C.5 超参搜索（Kaggle T4 / CPU 预算）

**【建议】** 搜索空间（LightGBM 为例）：

| 参数 | 候选 |
|---|---|
| `num_leaves` | {15, 31, 63} |
| `max_depth` | {-1, 5, 7} |
| `min_data_in_leaf` | {200, 1000, 5000} |
| `learning_rate` | {0.02, 0.05, 0.1} |
| `feature_fraction` | {0.6, 0.8, 1.0} |
| `bagging_fraction / bagging_freq` | {0.8/1, 1.0/0} |
| `lambda_l1 / lambda_l2` | {0, 1, 10} × {0, 1, 10} |
| `max_bin` | {63, 127, 255} |
| `n_estimators` | 早停，上限 2000，patience 50 |

**【建议】** 特殊约束：
- **单调约束**：对 `spread_bps`、`depth` 施加方向性单调（例如 fill 强度对 `spread_bps` 单调不增），能显著提升泛化与可解释性。【推断】需本机验证是否真的单调。
- **样本权重支持**：`set_weight` 支持时间衰减 + IPW 权重。

**预算**：

|---|---|---|---|

|---|---|---|---|---|---|---|

### C.7 推理延迟路径选择

**【建议】** 三级部署路径：

**路径 A（首选）：GBDT 主力 + 硬约束钳制 + A-S 降级**
- 组成：LightGBM（fill 强度）+ LightGBM（AS 回归）+ 闭式解 + 硬约束层
- 延迟：特征 50 + 推理 100（两个模型） + 钳制 10 = **~160 μs**
- 优点：可解释、可增量更新、可随时回滚、CPU 友好
- 缺点：特征工程依赖强

**路径 B：GBDT 主力 + 神经辅助信号**
- GBDT 负责 fill/AS 主输出；小型 MLP 负责一个**低维辅助头**（例如"未来 30 秒不利移动的符号置信度"），只输出 1~3 维
- MLP 输入必须是 GBDT 的特征子集 + GBDT 的输出（stacking）
- 延迟增加 5~20 μs
- **价值有限**：只有在 MLP 能捕捉 GBDT 捕捉不到的结构时才有意义，**必须用消融实验证明增量**（模型 A vs 模型 A+MLP 的净期望差异 > 0.3 bps/笔）

**路径 C（推荐用于降本/降延迟）：蒸馏**
- 教师：GBDT 集成（或 GBDT + 校准器 + 闭式决策的完整流水线输出）
- 学生：2 层 MLP（32-64-32），输入 = 归一化特征，输出 = `log λ̂`（各 δ）与 `markout̂`
- 蒸馏损失 = KL(teacher soft) + MSE(teacher 的最终 δ* 决策)
- **【建议】** 蒸馏的真正价值不是延迟（GBDT 已够快），而是**把决策边界平滑化**，可能降低边界抖动（报价频繁改动 → 撤单重挂 → 手续费与队列损耗）。这个假设**必须实测**：比较"策略稳定度"（每分钟撤单次数、报价变动次数）作为副指标。

**【建议】** 路径 A 上线，路径 C 作为第二阶段（把 GBDT 教师 + MLP 学生 + 一致性监控一起上线，MLP 只在 GBDT 不可用时接管）。

## D. 滚动重训与漂移检测

### D.1 重训节奏

**【建议】** **时间为主 + 事件为辅**：

| 触发 | 条件 | 动作 |
|---|---|---|
| 定时（日） | 每 UTC 00:00 | 用滚动 30 天窗全量重训 + 走完 walk-forward 验证 + 上线 challenger |
| 定时（周） | 每周一 | 数据集全量重建（含重新打标、重新校准）+ 全量超参复核 |
| 事件：数据量 | 累计新增样本 > 5% 训练窗规模 | 触发一次增量训练（`init_model` 继续训练），不重跑超参 |
| 事件：漂移 | PSI 红 ≥ 3 小时 或 特征健康红灯 | 触发**紧急重训**（缩短到 14 天窗，强调近期数据） |
| 事件：策略退化 | 影子/灰度回测净期望连续 3 日为负 | 触发重训 + 触发回滚流程 |

**【实测约束】** 1 核 1G 上 LightGBM 全量训练内存不够（§C.1），**因此 VPS 上不做训练**。方案：
- 训练在本地工作站 / Kaggle 完成，产出模型包（含元数据，§D.6）。
- VPS 上有一个**轻量的"训练请求"作业**：采集滚动 30 天的实盘特征 + 事件日志 → 落盘为数据包 → 定期同步到训练机（或定期上传到临时存储）。
- **【建议】** 第一版直接**离线训练 + 手动/脚本部署**，把自动化留到后面（YAGNI）。日更节奏用 cron 拉取训练产物即可。

### D.2 在线特征分布漂移

**PSI**（Population Stability Index）：
```
PSI = Σ (p_i − q_i) · ln(p_i / q_i)
```
p = 当前窗口（最近 24h）分布，q = 训练集分布（用分位数分 10 桶）。

| PSI | 判定 | 动作 |
|---|---|---|
| < 0.10 | 绿 | 无 |
| 0.10 ~ 0.25 | 黄 | 记录；下次重训提高该特征时间衰减敏感性；人工抽查 |
| > 0.25 | 红 | **该特征暂时从模型输入中剔除**（用备份模型/均值填补）→ 立即重训 |

**KS 统计量**（对每个特征单独算，作为 PSI 的补充）：
- `KS_2samp(p, q) > 0.2` 或 p 值 < 0.01 → 记为漂移候选。
- **【建议】** KS 捕捉"形状变了但 PSI 不敏感"的情况（例如双峰变三峰），但对连续型特征的多重检验需要校正（Benjamini–Hochberg）。

**均值/方差漂移**：
```
mean_shift = (μ_live − μ_train) / σ_train     （标准化均值差）
```
- `|mean_shift| > 0.3` → 黄；`> 1.0` → 红。
- 同时监控 `σ_live/σ_train`，比值 < 0.5 或 > 2 → 红（特征被"压扁"或"爆掉"，通常意味着采集 bug）。

**【建议】** 必须加**采集健全性检查**（区别于"市场漂移"和"代码坏了"）：
- `quote_age_ms` P99 > 500 ms → 采集延迟异常
- `book_gap_flag` 突然上升 → 深度档位截断（realms 报错）
- 特征方差为 0 的连续时长 > 5 分钟 → 计算管道卡死
- 状态数量与交易所一致 → 校验 `Q_b1 > 0` 等不变量

### D.3 标签漂移与策略退化的快速检测

**问题**：等一天看回测 PnL 太慢；实盘样本又极少（当前规模：40 小时 2123 笔）。

**【建议】** 三层快速检测：

**第 1 层：影子成交（paper fill）—— 最快，样本免费**

在实盘每条 book 更新时，维护一个**虚拟队列**：
- 假设我们在当前买一/卖一各挂了 1 张（0.01 张）
- 按真实成交方向与数量推算排队位置变化，模拟"如果我在队列里，什么时候会成交"
- 每个事件记录一次"影子成交事件"及其**当时预测的 markout**

**关键**：影子成交是用**实盘真实行情**在**实时**产生的，不消耗本金、不产生手续费，因此样本量可以很大（每天数千条影子事件）。
**【建议】** 这是本设计里性价比最高的一块基础设施，因为它把"策略验证"从"等真实成交"变成"免费获得样本"。

**影子指标**（每 1 小时滚动更新）：
| 指标 | 定义 | 告警 |
|---|---|---|
| 影子净期望 | `capture − fee − E[markout]`（bps） | < 0 → 红 |
| 影子 markout | 成交后 5s 的 markout 均值 | 买单 < −1.5 bps → 黄，< −2.5 bps → 红 |
| 影子命中率 | 实际成交 / 影子成交 | < 0.7 → 红（队列模型失真） |
| 影子 vs 实盘偏差 | 同价位同期两者的成交时间差 | 持续 > 1s → 黄 |

**第 2 层：实盘小样本滑窗**
- 维护最近 **200 笔实盘成交**的滚动统计：净期望 bps、markout bps、胜率、手续费占比。
- **【建议】** 200 笔在当前规模下约需 3~4 小时【推断】（按 40.96h/2123 笔 ≈ 0.019 笔/秒 ≈ 71 笔/小时）→ **能在半天内发现退化**。
- 显著性：用 `t` 检验的 95% CI 下界判断（`mean − 1.96·se > 0`）。样本小 → 用 **bootstrap**（不做正态假设）。

**第 3 层：日终全量复核**
- 与队列感知回测的对应时段对比（§F.3），差异 > 30% → 怀疑实盘环境漂移或回测模型失真。

### D.4 Champion / Challenger 架构

```
                 ┌─────────────────┐
   特征流水线 ───►│ Champion (当前) │──► 硬约束层 ──► 报价 ──► 下单
                 └─────────────────┘
                 ┌─────────────────┐
                 │ Challenger(影子) │──► 硬约束层 ──► 影子报价（只记录不下单）
                 └─────────────────┘
```

**【建议】** 晋级路径（每级最短驻留时间 + 晋级门槛）：

| 阶段 | 时长 | 门槛 |
|---|---|---|
| 影子 | ≥ 3 天（覆盖 ≥ 3 个波动 regime） | 影子净期望 > 基线 + 0.5 bps/笔；无 NaN/超时；决策稳定性（报价变动次数/小时）不劣化 > 20% |
| 小资金灰度 | ≥ 3 天，10% 资金 | 实盘净期望 > 0（bootstrap 95% CI 下界 > 0）；手续费占比 < 35%；Taker 比例 < 0.5% |
| 全量 | ≥ 7 天 | 上述全部 + 无回滚触发 |

**【实测】** Taker 比例是硬红线：旧版 dayuan 40.96h 内 Taker 占 30.9%，手续费占总亏损 72.6%。**【建议】** `taker_ratio > 1%` 立即停用 ML 报价（连同 Post-Only 一起验证）。

**回滚触发条件（任一命中即回滚到上一版 Champion）**：
1. 滚动 200 笔净期望的 95% CI 下界 < 0
2. `taker_ratio > 1%`
3. 决策超时率 > 1%（P99 > 200 μs 的比例）
4. 特征 PSI 红 ≥ 3 小时且无法通过剔除特征恢复
5. 报价违反硬约束（库存超限、跨盘口、低于手续费门槛）——**任何一次都必须回滚**，因为这说明决策链路有 bug 而不是市场问题
6. 单日回撤 > 阈值的 2 倍

**回滚机制**：模型包版本化部署，`rollback` = 切回上一个 registry 版本（秒级，只需重启决策进程，不需回滚数据）。

### D.5 Champion/Challenger 的具体接口

```python
# live_cluster/ml_decision.py
class DecisionEngine:
    def __init__(self, registry_path, fallback: "ASFallback"):
        ...
    def decide(self, ctx: MarketContext) -> QuoteDecision:
        feats = self.featurizer.update_and_snapshot(ctx.event)   # 纯因果
        if self.champion.health_ok(feats) and self.model_valid:
            raw = self.champion.predict(feats, ctx.side)
            quote = self.decision_map(raw, ctx)          # §E
```

## E. 从模型到交易决策的映射（核心）

### E.1 原则

1. **模型输出不是报价**，是三个原语：
   - `λ̂(δ, side)`：成交强度（Poisson log-link 的 λ）
   - `â(δ, side)`：成交后的**期望逆向选择成本**（bps，正数表示成本）
   - `m̂(δ, side)`：成交后的 markout 符号置信度（辅助，用于两侧不对称调整）
2. **报价由闭式/数值优化从原语解出**，不直接由模型回归。
3. **A-S 解析解提供保留价格 `r` 与基准距离 `δ_base`**，ML 只做残差修正。
4. **所有硬约束在最后一层钳制**，模型不能绕过。

### E.2 期望单笔净收益的分解

对买单侧、挂单距离 δ（相对 mid 的 bps）：

```
Π_bid(δ) = P_fill(δ) · [ δ − f_maker − a_bid(δ) − c_inv(δ) ]  − P_fill(δ)·λ_tox·c_tail
```
拆解：
| 项 | 含义 | 来源 |
|---|---|---|
| `P_fill(δ)` | H 内成交概率 | 任务 1（Poisson：`1 − exp(−λ̂(δ)·H)`） |
| `δ` | 半价差捕获 | 决策变量 |
| `f_maker` | Maker 手续费（bps/边） | 【实测】2 bps |
| `a_bid(δ)` | 成交后的期望逆向选择成本（bps） | 任务 2 回归输出 |
| `c_inv(δ)` | 库存成本 | A-S：`q·γ·σ²·T` 折算到每笔 |
| `λ_tox·c_tail` | 尾部损失期望（被扫盘） | 任务 2 分类头 |

**单位时间价值**（决策真正关心的是"每秒赚多少"，因为撤单/重挂有机会成本）：
```
V_bid(δ) = P_fill(δ) · [ δ − f_maker − a_bid(δ) − c_inv(δ) ] / H
```
**【推断】** 除以 H 会让"慢成交"被正确惩罚——这正是 Poisson 强度模型比二分类模型更适合做市决策的原因。

### E.3 闭式解与数值解

#### E.3.1 闭式解（距离衰减为指数时的特例）

若模型给出 `log λ(δ) = log λ₀ − θ·δ`（θ > 0，距离衰减指数），且 `a_bid(δ) ≈ a` 与 δ 无关：

```
V(δ) = (1 − e^{−λ₀e^{−θδ}·H}) · (δ − f − a − c_inv) / H
```
在"成交概率近似线性于小 δ"区域，或用泊松近似的**指数近似** `P_fill ≈ λ₀e^{−θδ}·H`（当 `λH ≪ 1`）时：
```
V(δ) ≈ λ₀ e^{−θδ} · (δ − c)   ，其中 c = f + a + c_inv
```
最大化：`dV/dδ = 0 → δ* = 1/θ + c`

**这就是本设计的核心公式**：
```
δ*_bid = 1/θ_bid + f_maker + a_bid + c_inv
```
其中：
- `1/θ` = **排队/到达强度的距离衰减尺度**（模型给出）
- `f_maker` = 手续费（常量，实测 2 bps）
- `a_bid` = 逆向选择溢价（模型给出）
- `c_inv` = 库存成本（A-S 给出，随库存变化）

**验证**：`δ* ≥ 1/θ` 恒成立，且 `a` 越大距离越宽——符合做市直觉（毒性强则远离）。**这是一个可解释、可审计、参数含义清晰的决策规则**，也是本切片最推荐的落地形式。

**【推断】** 该闭式解在 `λ₀H ≪ 1` 时准确；在高强度时段（`λ₀H ~ 1`）偏差增大。**【建议】** 生产上**用数值解**（在 δ 网格上直接最大化 `V`），闭式解作为可读的解释与降级基线。

### E.4 硬约束钳制层（位置与接口）

**【建议】** 顺序固定为：
```
模型 → 决策映射（算 δ*） → 【硬约束层】 → 报价下发
```
钳制层是**纯函数、无状态、可单测**，输入 `QuoteDecision` 与 `MarketContext`，输出被钳制后的 `QuoteDecision`。

```python
@dataclass
class QuoteDecision:
    bid_price: float
    ask_price: float
    allow_bid: bool
    allow_ask: bool
    delta_bid_bps: float
    delta_ask_bps: float
    reason: str            # 可解释性：哪条约束生效了
    model_id: str
    feature_snapshot: dict  # 落盘用，影子/审计

class RiskLayer:
    """硬约束层。所有约束不可被模型绕过。"""
    def clamp(self, d: QuoteDecision, ctx: MarketContext) -> QuoteDecision:
        # 1) 手续费门槛：总报价价差 ≥ 9.0 bps（实测下限），单向 δ ≥ 4.5 bps
        # 2) tick 对齐：OKX tick = 0.1 USDT
        # 3) 不跨盘口：bid ≤ best_bid，ask ≥ best_ask（Post-Only 冗余保险）
        # 4) 库存上限：ctx.inventory ≥ max_inventory → allow_bid = False（卖单反向）
        # 5) ADX 强趋势阻断：adx ≥ 28 且 trend_dir 与挂单方向相反 → 禁止
        # 6) 成交冷却：成交后 5 秒内该侧禁止
        # 7) 毒性断路：P_tox ≥ 0.65 → 该侧禁止
        # 8) 数据陈旧：quote_age_ms > 500 → 双侧禁止（不报价）
        # 9) 决策超时/特征缺失 → 双侧禁止
        return d
```

**【建议】** 上述 9 条与现有 `as_nautilus_strategy.py` 的实现**保持一致**（9.0 bps 门槛、ADX 28、0.65 毒性阈值、5 秒冷却），ML 只提供**连续量**（δ*、p_tox），把离散门限的判断留给钳制层。这样：

- ML 可以**放宽**也可以**收紧**距离，但不能突破绝对底线；
- 回滚时只需把模型换回 A-S 解析解，钳制层不变；
- 行为可审计：`reason` 字段记录每次钳制的触发项。

**额外建议**：钳制层应支持"**只收紧不放松**"模式（`model_max_authority`）。上线初期用 `max_authority=0.5`（模型只能在 A-S 基线的 ±50% 内调整距离），观察一周后再放开到 1.0。**【建议】** 这能把上线风险再压一半。

### E.5 降级路径（模型失效时安全退化）

**降级阶梯**（自动触发，无需人工介入）：

| 级别 | 触发条件 | 行为 |
|---|---|---|
| L0 正常 | 模型健康、特征 PSI 绿 | 模型 δ*，受钳制 |
| L1 保守 | 特征 PSI 黄 / 单特征红 | 用**剔除该特征**的备用模型（已预先训练）；若无，用 L2 |
| L2 解析解 | 模型推理超时 / NaN / 校准漂移 | `δ_A-S = (1/γ)·ln(1+γ/κ)`，按 mid 的 bps 缩放，加 9.0 bps 价差下限 + 现有全部硬约束 |
| L3 双侧停挂 | 行情陈旧 / WS 断连 / 决策超时率 > 1% | 不报价，撤掉全部挂单 |

**【建议】** L2 的 A-S 解析解必须**独立于模型包**实现（纯常量与公式），并有独立单测。这样即使模型文件损坏、registry 索引丢失、Python 依赖升级，系统仍能报价。

**【建议】** 降级必须是**可观测**的：每次降级写事件日志（Telegram 告警 + JSONL），并统计"降级期间收益"。若 L2 长期比 L0 好，说明模型有害。

### E.6 模型信号无效时的安全判定

**【建议】** 除漂移外，加一个**信号有效性哨兵**：
- 在实盘持续计算"模型预测的 δ* 与 A-S 基线 δ 的差"的滚动分布。
- 若 `|Δδ|` 的中位数持续为 0（即模型输出退化成常数），说明模型实质失效（可能是校准器把所有输入映射到同一档）。
- **【建议】** 哨兵指标：`δ*_std_24h`（模型距离的 24 小时标准差）。低于阈值（【建议】`0.2 bps`）→ 视为退化成常量 → 降级到 L2。

### E.7 单位与量纲规范（必须遵守）

**【建议】** 全链路统一：
- 所有距离、价差、成本：**mid 的 bps**（无量纲）
- 所有库存成本：A-S 形式 `q · γ · σ² · T`，其中 σ 用 **bps/√s**、T 用秒、结果得到 bps
- 报价落地时才转回价格：`price = mid · (1 ± δ_bps/1e4)`，最后按 tick 对齐
- **【实测/待修】** 现有 `as_ml_engine.py` 的库存偏置写作 `q·γ·σ²·mid·0.001`，把 bps 单位的 σ 与价格单位的 mid 相乘，量纲不干净。**【建议】** 在 ML 决策层统一用 bps 口径，旧的 `as_ml_engine` 保留为 L2 降级路径（并在文档中标注其参数是启发式标定值，不是量纲一致的解）。

## F. 训练与实盘的闭环验证（防幻觉）

### F.1 训练/实盘特征一致性对拍（最高优先级）

**这是最容易"训练很好、上线即废"的地方。**

#### F.1.1 三层对拍

**层 1：同一份代码**
- 特征只实现一次：`src/ml/l2_features.py`，离线与实盘都 `import` 它。
- **【建议】** 加 CI 检查：`grep -rn "def compute_" live_cluster/ src/ | grep -v ml_features` 不应出现第二份特征实现（用 lint 规则或简单脚本）。

- 离线用同一批文件重放 → 得到特征序列 → 与实盘当时记录的 `feature_snapshot` 逐字段比对。
- **门槛**：所有字段 `max|diff| ≤ 1e-9`（浮点用相对容差 1e-7）。任何一列不过 → CI 失败。

**层 3：同一个事件序列 → 两条流水线**
- 把实盘 WS 事件流离线重放（EventLog），跑**离线特征流水线**；
- 与**实盘特征流水线**（在线增量状态机）对比。
- 目的：抓"在线用增量状态、离线用全量重算"的不一致（这类 bug 最常见：例如 OFI 的上一快照在离线被"最后一条快照"覆盖而不是"上一条"）。

#### F.1.2 分布对拍（不只是逐字段相等）

逐字段相等只保证代码一致，不保证**特征口径与实盘可得性一致**。还要做：

**【建议】** 上线前必查三项：
1. **深度档位数一致**：训练与实盘的 `books5`（5 档）vs 离线 L2 的档位数。凡是依赖 >5 档的特征（`conc_top1_top10`、`depth_slope` 用 20 档、`convexity`），**必须标记为 `F_deep` 并排除出上线模型**。
2. **延迟口径一致**：训练标签用的是归档数据（无采集延迟），实盘有 45~75ms RTT + 10~50ms 抖动。**【建议】** 在训练中加入一个"决策延迟"特征（如 `decision_lag_ms` 的滚动统计），或在标签构造时**向后偏移一个典型决策延迟**（例如用 t₀ + 60ms 时刻的特征做预测）来对齐。**【建议】** 首选做法：训练时把**决策时点**定义为"信息到达后 60ms 的时刻"，而不是事件 ts。
3. **实盘特征分布 vs 训练分布**：用实盘连续 7 天的 `feature_snapshot` 日志算 PSI（§D.2）。**门槛：所有上线特征 PSI < 0.1**。

### F.2 回测必须队列感知（与并行 worker 的接口契约）

**【建议】** 明确写出对回测引擎的**最小需求**，作为对接契约：

```python
# 期望的回测引擎接口（由回测 worker 实现）
class QueueAwareEngine:
    def step(self, ts_ns: int, book: BookSnapshot, trades: list[Trade],
             my_orders: list[MyOrder]) -> StepResult:
        """推进一个事件。必须：
        - 维护每个价位的价格-时间优先队列
        - my_orders 记录其在队列中的位置（前方挂单量）
        - 只有当队列前方量被消耗完且有足够成交量时才判定成交
        - 返回：成交明细（含成交价、成交量、成交时 my_order 的队列位置）、我的订单被取消/撤销事件
        """
```
**必须包含的物理要素**（否则做市收益会被系统性高估）：
1. **价格-时间优先 FIFO**（共享上下文已强调）
2. **队列位置跟踪**：我方挂单在同价位队列中的名次 = 该价位在我挂单之前累积的挂单量
3. **部分成交**：大单只能吃到部分深度
4. **撤单延迟**：撤单指令从发出到生效的延迟（【实测】RTT 45~75ms）
5. **撤单后剩余时间**：撤单生效前仍可能成交
6. **主动方判定**：成交方向（决定是任务 1 的"主动卖打我的买"还是别的）

**【建议】** 与回测 worker 明确：训练标签的构造也必须用同一套队列语义。**否则训练出的 fill 模型在回测里用另一个语义评估，会出现"训练指标好、回测指标差"的无法解释现象。**

### F.3 过拟合检验

| 检验 | 做法 | 门槛【建议】 |
|---|---|---|
| 样本/参数比 | 有效参数量 ≈ `num_leaves × depth`（GBDT）或权重数（MLP）；要求 `n_samples / n_params ≥ 100` | 不达标则减容量 |
| 每特征样本量 | 稀有事件样本（如毒性成交）每分裂至少 500 正样本 | 达不到则提高合并粒度 |
| 特征重要性稳定性 | 各折的 gain 重要性做 Spearman 相关 | 跨折中位相关 ≥ 0.6，否则剔除不稳定特征 |
| **SHAP 漂移** | 每月在固定样本上算 SHAP，比较方向向量的余弦相似度 | 与训练期相似度 ≥ 0.7 |
| **多重检验记账** | 记录所有试过的变体数（特征集 × 超参 × 标签定义） | 最终指标必须与"随机选一个变体的最好运气"有显著差距（跑 50 次随机变体做零假设分布） |
| 时间外验证 | 最后 10 天完全封存，只在最终模型上跑一次 | 只允许跑一次；报告要写明"此为一次性终评" |
| 打乱标签检验 | 把标签在**事件内**随机打乱（保留时间结构）重训 | 指标应回落到随机水平；若仍高，说明泄漏 |

**【建议】** 最后一项是防泄漏的"照妖镜"，成本极低（一次训练），必须做。

### F.4 收益归因

**【建议】** 每笔成交与每个时间桶的 PnL 必须拆成：
```
PnL_total = Capture − Fee − AdverseSelection − InventoryCost − LatencyCost
```
| 项 | 定义 | 测量方式 |
|---|---|---|
| `Capture` 价差捕获 | 相对**成交时刻 mid** 的半价差：`side_sign × (P_fill − mid_at_fill)` | 成交回报的 `fill_price` 与本地 mid 快照比对（同一事件流） |
| `Fee` 手续费 | Maker 2 bps 或 Taker 5 bps × 名义 | 由成交回报直接累加（**用交易所返回的 fee 字段，不用自己算**） |
| `AdverseSelection` 逆向选择 | `side_sign × (mid(t₀+T) − mid_at_fill)` | 用同一事件流重建 mid，取 T=5s |
| `InventoryCost` 库存成本 | `q · γ · σ² · T` 的累计（A-S 内部成本项） | 逐事件按 A-S 记账；**它是一个再分配项**，与 markout 有重叠 |
| `LatencyCost` 延迟成本 | `side_sign × (mid_at_fill − mid_at_decision)` | 决策时刻 mid 与成交时刻 mid 的差，**直接度量 RTT+抖动+撮合延迟的价值损耗** |

**【推断】** 关键分解恒等式（用于闭合校验）：
```
Capture + AdverseSelection − Fee − LatencyCost = 实际现金 PnL − InventoryCost
```
**【建议】** 回测与实盘都跑这个**闭合校验**，残差必须 ≈ 0（相对名义 < 1e-6）。残差不为零 = 记账漏项，这比"策略赚不赚钱"更值得先查。

**【建议】** 额外按 **side × 距离档 × 时段 × 事件类型** 做四维归因表，找出"哪一类成交在亏钱"。这个表是 §E 决策映射调参的直接输入。

## 8. 算力与数据预算（1 核 1G 能做 / 不能做）

### 8.1 VPS（1 核 1G，多容器共享）——**只能做推理与监控**

| 能做 | 不能做 |
|---|---|
| 特征增量计算 + LightGBM 推理（< 200 μs/次） | 全量训练（内存不够，§C.1） |
| 影子成交/纸面标记（无成本产生样本） | 全量 L2 事件日志重放（I/O + CPU 不够） |
| 滚动 IC / PSI / 分布监控 | 队列感知回测（CPU 太慢） |
| 特征健康检查、数据健全性检查 | 大规模超参搜索 |
| 模型包拉取与热切换 | — |
| 采集原始事件落盘（限速、限容量） | 保存长周期全量 L2（磁盘也不够） |

**内存账**：1G 共享，多容器。Python 进程基础占用约 150~250 MB（numpy + lightgbm + nautilus）。特征状态约 5 档 × 若干滚动缓冲 ≈ 几 MB。**推理链路可控在 400 MB 以内**。任何训练尝试都会 OOM。

### 8.2 本地工作站 / Kaggle —— 训练与回测

| 项 | 需求 |
|---|---|
| 训练数据（30 天 × 100ms 栅格） | 260 万行 × 24 特征 float32 = 250 MB（内存 OK，磁盘需 ≥ 2 GB） |
| 归档下载 | cryptohftdata 按小时 parquet，**30 天 × 24 = 720 个文件**；需实测单文件大小与下载速率（§9 待校准项） |
| 一次 walk-forward（60 折） | 本地 8 核 ≈ 40 min ~ 2 h；Kaggle ≈ 2~6 h |
| 队列感知回测（30 天 tick 级） | 取决于事件数；**【推断】** 100ms 栅格 260 万事件 × 单事件 O(档数) → 数十秒~数分钟（可行）；若全 tick 则需评估 |
| 磁盘 | 建议 ≥ 50 GB 归档缓存 + 5 GB 特征缓存 |

### 8.3 磁盘与采集的现实约束

**【建议】** VPS 上采集原始事件的容量控制：
- 只存 5 档 book（与实盘一致）+ 成交，**不存全量 L2**；
- 环形缓冲保留最近 24~72 小时；
- 同步策略：每 5 分钟打包一次 + gzip 传输到训练机（**【实测】** 带宽不是瓶颈，45~75ms 是延迟不是带宽）。

## 9. 「学术已知结论」 vs 「需要本机实测校准的假设」

### 9.1 学术/文献已知（可直接依赖，但需确认在本场景的量级）

| 结论 | 来源 | 本设计的用法 |
|---|---|---|
| 最优半价差 `δ = (1/γ)·ln(1+γ/κ)`，保留价格含 `−qγσ²T` | Avellaneda & Stoikov (2008) | 作为基线与库存项（§E） |
| OFI 对短期价格有显著预测力，强度随流动性变化 | Cont, Kukanov, Stoikov (2014) | §B.2 的特征设计；**量级需重估** |
| 微观价（microprice）是比中价更好的短期价格预测量 | Stoikov (2018) | §B.1 `micro_dev_bps` |
| 限价单成交概率与队列位置近似线性（队列短时） | Huang, Lehalle, Rosenbaum (2015) | 解释为什么 `1/θ` 是"队列尺度"；**实盘 5 档队列需实测** |
| 订单到达可用 Poisson 强度建模 | Huang & Polak (2011) | §A.1.2 的 Poisson 模型 |
| 回测必须用 purged CV + embargo 防标签重叠泄漏 | López de Prado (2018) | §C.2 |
| 逆向选择在加密市场普遍存在，且随波动放大 | 多篇微观结构文献 | §A.2 的存在性依据 |
| VPIN 作为毒性代理存在争议/自反性 | Easley-López de Prado-O'Hara (2012) 及后续批评 | §B.4 的谨慎处理 |

### 9.2 必须本机实测校准的假设（本设计的待验证清单）

| # | 假设 | 怎么测 | 若不成立的后果 |
|---|---|---|---|
| H1 | cryptohftdata 的 `orderbook` 归档是**增量**还是**快照**；深度档位；时间戳精度 | 下载一个小时的 okx_futures orderbook parquet，检查 size 是否单调（增量）或绝对（快照）；检查相邻 ts 的价格连续性 | 决定 OFI 与形状特征能否离线重建。**这是第一号阻塞项** |
| H2 | 归档数据与实盘 `books5` 的档位/字段口径一致 | 用归档同时段重建 5 档 mid，与实盘日志 mid 逐条比对 | 特征口径不一致 → 训练/实盘分布错位（§F.1） |
| H3 | `1/θ`（距离衰减尺度）的典型值与稳定性 | 从填充模型直接读出 θ 的分布，按日/时段统计 | 决定 δ* 的量级；若 θ 极不稳定，闭式解失效，须回退到网格数值解 |
| H4 | 逆向选择成本 `a` 的量级（bps） | 用影子成交 + markout 直接测量 | 若 `a` > 2.5 bps，则**任何做市都不可能盈利**（§0.2），这是整个策略的前提，必须最先测 |
| H5 | 队列前方挂单量的分布（决定真实成交率） | 队列感知回测 + 影子命中率校准 | 决定 Poisson 强度是否需要队列位置特征 |
| H6 | 45~75ms RTT + 10~50ms 抖动对成交率与逆向选择的实际影响 | 对比"理想延迟回测"与"实测延迟回测" | 若影响巨大，模型的训练标签必须按实测延迟偏移 |
| H7 | `books5`（5 档）是否足以支撑形状类特征 | 计算 5 档与 20 档特征的相关系数与互信息 | 若不足，则实盘必须升级到 `books50`/L2 深度（工程量评估） |
| H8 | 跨交易所 lead-lag 是否在 50ms 尺度存在且稳定 | 与第二路行情的时间戳对齐分析（需第二路采集） | 若不存在，第一版不上线跨所特征 |
| H9 | 资金费率/基差对秒级决策是否有增量预测力 | 特征消融 + 净期望增量 | 若 < 0.2 bps/笔则不纳入 |
| H10 | LightGBM 在本机 1 核上的实际推理延迟 P99 | §C.6.1 脚本在 VPS 上跑 5000 次 | 若 > 200 μs → 走蒸馏路径 C |
| H11 | 训练数据的下载量与速率 | 实测每小时 parquet 大小 × 720 | 决定是否需要分批/裁剪策略 |
| H12 | 影子成交模型与真实成交的偏差（命中率） | 影子 vs 实盘 200 笔比对 | 若偏差大，影子只能做相对趋势监控，不能做绝对判断 |

**【建议】** 实施顺序：**先做 H1、H4、H5、H10**（这四个决定项目是否成立），再做特征工程与训练。
- H4（逆向选择量级）如果 > 2.5 bps，那么整个方向都要重估——这比训练任何模型都重要。
- H1 如果归档是快照而非增量，OFI 类的**逐档增量特征无法离线重建**，只能退化为"快照差分 OFI"（近似版），特征价值会下降。
